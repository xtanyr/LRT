## Исправления перед тестом

- Исправлены выход из аккаунта, вход с пробелами/другим регистром email и проверка некорректных данных запроса.
- Добавлены обработка ошибок справочников и конфигурации, повторные попытки и защита от повторных сохранений.
- Исправлены ограничение ширины полей, мобильные карточки, формы назначений, модальные окна и выбор периода.
- Максимум рейтинга в методологии корректно учитывает числовые строки API; цвет итога отчёта использует настройки сервера.
- Уточнён текст обучения и обозначения метрик.
- Лимит Nginx увеличен до 25 MB; HTML не кешируется, файлы сборки кешируются по их уникальному имени.
- Runtime-образ API собирает собственные зависимости backend, включает Prisma для миграций и исключает средства разработки.

## Границы проверки

Реальный Ubuntu-сервер, его внешнее проксирование и TLS после обновления необходимо проверить командами из гайда. Нагрузочное тестирование и реальная отправка почты/Google OAuth не выполнялись; доставка восстановления пароля и OAuth требуют серверных credentials. Внешние источники показателей не подключены, значения вводятся вручную.

В production-зависимостях `npm audit --omit=dev` остаются 3 записи high и 0 critical, относящиеся к одной цепочке `prisma` → `@prisma/config` → `deepmerge-ts` 7.1.5. [Advisory](https://github.com/advisories/GHSA-ggr8-5vv4-36mx) описывает исчерпание стека при слиянии циклических объектов; исправление находится в несовместимой версии 8. По просмотренному коду эта цепочка используется CLI Prisma для конфигурации, а не обработчиками HTTP. Это ограничение проверки, а не заявление о полном отсутствии уязвимостей; обновление Prisma следует проверять отдельно вместе с миграциями.

Независимое финальное ревью не выявило оставшихся замечаний к проверенным изменениям. Выполнение очистки на сервере остаётся отдельным шагом владельца сервера.
