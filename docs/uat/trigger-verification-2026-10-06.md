# Исправление и проверка триггеров ИПВ — 6 октября 2026

Найденные при [аудите](trigger-audit-2026-10-05.md) ошибки исправлены в рабочей копии `C:/LRT`. Проверены backend, затронутые экраны и настоящая цепочка Nest HTTP → Prisma → PostgreSQL. Сервер `lrt.scr-tech.ru` не обновлялся; рабочая Docker-база не менялась.

## Что изменилось

- Монитор учитывает действующие назначения лидеров кофейни. Завершённое/будущее назначение или другой лидер без достаточного стажа/утверждения больше не блокирует подходящего текущего лидера.
- T1 проверяет три месяца ниже 60 без роста; T2 — двенадцать месяцев ниже 80 с допустимым ростом; T3 — одну и ту же критичную метрику три месяца подряд. Окно заканчивается предыдущим календарным месяцем по Москве. Пропуск месяца, черновик или отсутствие сохранённого рейтинга не создают событие.
- При запуске API создаются отсутствующие настройки 3/12/3 и 6/6. Пользовательские настройки сохраняются. Порог, число месяцев, стаж и активность доступны в редакторе конфигурации; некорректные значения отклоняются.
- «Проверить сейчас» запускает тот же монитор для доступных пользователю кофеен. «Мониторинг кофеен» показывает окно, текущих лидеров и причины отсутствия срабатывания, включая пустую дату утверждения.
- Ручные исключения доступны в интерфейсе. Они скрывают ожидающие события, индикаторы и активные уведомления; снятие возвращает сохранённые сигналы. Автор сохраняет возможность снять своё исключение после перевода лидера или снятия назначения; COO и администратор могут снять любой флаг.
- Одновременные причины T1/T3 сохраняются отдельно, но относятся к одному ИПВ кофейни. Начало и завершение применяются ко всем причинам; при старте все связанные уведомления становятся прочитанными, при завершении сохраняется общий итог. Дашборд считает один ИПВ на кофейню и отдаёт приоритет индикатору «В работе».
- Повторные и одновременные проверки не дублируют события/уведомления и не меняют исходную дату. Завершённое ИПВ не открывается заново за то же окно; новое окно может создать новое срабатывание. ИПВ в работе блокирует новую генерацию.
- Уведомления получает только лидер города с уже начавшимся назначением. Бывший лидер города после смены роли и будущий назначенный лидер не получают новые уведомления. Просрочка после 14 дней остаётся визуальным состоянием без автоматической эскалации.
- В событиях видны дата по Москве, конкретная метрика T3 и итог завершения. Карточка кофейни получает только её события. Ошибки загрузки и действий показываются пользователю; устаревший ответ после смены кофейни не заменяет текущие данные.
- Импортированная история с политикой `preserve-source-score` остаётся доступна только для чтения даже при `ALLOW_HISTORICAL_REPORT_EDITING=true`: исходные рейтинги сохраняются. Для испытаний используются отдельные синтетические отчёты.

Полные интерфейсные и серверные наборы не запускались. Проверялись изменённые части и связанные с ними сценарии. Отдельные тесты воспроизвели ошибки до исправления: блокировка текущего лидера историческим назначением, несколько причин одного ИПВ, лишние адресаты уведомлений, собственный флаг после перевода лидера и ответ старой карточки после смены маршрута.

Сквозной сценарий — `backend/test/trigger-acceptance.cjs`. Он разворачивает миграции в пустой базе с именем `lrt_trigger_test`, запускает настоящий Nest API и проверяет T1/T2/T3, границы 60/80, стаж/утверждение, роли и города, исключения, общий процесс ИПВ, итог закрытия, просрочку, конкурирующие запросы, новые окна и конфигурацию. Тест отказывается работать с другим именем базы или непустыми пользователями/кофейнями. При запуске использовались отдельные контейнер PostgreSQL и сеть; API-контейнер не публиковал порты. После проверки временные ресурсы удалены.

## Применить в локальном Docker на Windows

Из `C:\LRT`:

```powershell
docker-compose -p lrt up -d --build --no-deps api web
```

Затем обновите страницу. Порядок ручной проверки — в [сценарии для стейкхолдеров](stakeholder-test-guide.md). Само наличие отправленных demo-отчётов не гарантирует совпадения с T1/T2/T3; реальные даты назначения/утверждения и рейтинги автоматически не подменяются.
